Kimi-K3 stacks it 93 times at 2.8 trillion weights. Mistral-7B stacks it 32 times at 7 billion. Strip a dozen flagship models down to one layer and the same shape keeps showing up: normalize, attend with shared key heads, normalize again, feed through a gated projection, add what came in. Mistral-7B established it in the open in 2023, Qwen2.5-7B refined it in 2024, and every mixture-of-experts, latent-attention and hybrid model in this course starts from it before adding its own idea.

This chapter runs one token vector through that block twice: once with Qwen2.5-7B's dimensions on channel A, once with Mistral-7B-v0.1's on channel B (the figure's two tracks: same operations, same token, different model). You will see what RMSNorm does, how 4 key heads serve 28 query heads, why Mistral stops looking past 4,096 tokens, and what one block costs in weights. The next chapters vary each piece.

The 2-minute version

Every model since ChatGPT stacks one decoder block: RMSNorm, grouped-query attention, RMSNorm, SwiGLU feed-forward, two residuals. Qwen2.5-7B and Mistral-7B differ only in widths, head counts and window — and the 2026 flagships are the same block with fancier attention and experts bolted on.

After this chapter you can: read heads, layers and widths from any config · compute KV bytes and block weights by hand · explain why the MLP dominates every block.

1.1The block both models share

Words to numbers

Token: the fragment of text a model reads, stored as one integer id. Vector: the list of hidden_size numbers that id becomes inside the model — the only thing the model ever operates on. Weights: the learned matrices that implement every operation. Block: the repeating unit this figure shows — normalize, attend, normalize, feed-forward, and the two residual adds that wrap each half. Widths: how long those vectors are (Qwen2.5-7B: 3,584 numbers; Mistral-7B: 4,096). Heads: the parallel lookup workers inside attention, meeting properly in 1.3. Channel A / B: the figure's left and right tracks — the same workload run through each design. The Start here page walks the deepest three (vectors, matrices, attention) in ten minutes.

The figure follows a single token's hidden vector from one block's input to the next. Both channels run the same six operations in the same order. They differ only in widths, in how many times shared heads repeat, and in how far back attention looks.

The two blocks agree on the recipe and disagree on the measurements. Qwen2.5-7B stacks this block 28 times at width 3,584 ; Mistral-7B stacks it 32 times at width 4,096 . Everything else in the chapter is a consequence of those two lines plus the head counts.

Reference setup

Single-model numbers in this course use bf16 weights and the pinned configs. Multi-GPU serving belongs to the sibling courses; here one block on one chip is the whole world.

1.2Normalize, attend, feed

A block does six things. RMSNorm scales the incoming vector by its own root-mean-square — the square root of the mean of its squares, then a learned gain; the epsilon that keeps the division safe is 1e-06 in Qwen2.5-7B and 1e-05 in Mistral-7B . Attention mixes the normalized vector with past positions Start here: normalization. A second RMSNorm follows, then a SwiGLU feed-forward: gate and up projections multiplied together, then down. Both models use SiLU as the hidden activation . Residual adds carry the input around each half — the block outputs input plus change, never a replacement — so depth never has to learn the identity.

The feed-forward's width sets most of the block's weights. Qwen2.5-7B expands 3,584 numbers to 18,944 and back ; Mistral-7B expands 4,096 to 14,336 and back . Three matrices each: gate, up and down. Qwen's block holds about 203.7M feed-forward weights against 29.4M in attention; Mistral's holds about 176.2M against 41.9M. The arithmetic is in the lab. The pattern to remember is the ratio: the MLP dominates, which is why later chapters put experts, sparsity and narrow formats there first.

Attention in one paragraph

Attention is a lookup. The current position builds a query: what am I looking for. Every earlier position carries a key: what it offers to answer — and a value: what it hands over when chosen. Matching the query against each key returns scores; the scores choose how much of each value to blend in. A head is one query-key-value pattern, and heads run in parallel so each pattern can watch for something different. That is all grouped-query attention shares: fewer key-value sources, repeated to serve the queries. Start here expands this to the full three-step lookup.

1.3Share the keys

Neither model gives every query head its own key and value heads. Qwen2.5-7B serves 28 query heads from 4 KV heads ; Mistral-7B serves 32 from 8 . The projections are sized by the KV count, not the query count. In Mistral's attention module the K and V projections output num_key_value_heads × head_dim numbers while Q and O use the full head count:

Before attention runs, the shared heads are repeated to the query count. Transformers does it with one verbatim function, the equivalent of repeat_interleave along the head axis:

Qwen2.5's modeling file carries its own copy of the same function and the same group computation qwen2/modeling_qwen2.py:149 qwen2/modeling_qwen2.py:196. The repeat factor is 7 for Qwen2.5-7B and 4 for Mistral-7B. Repeating is cheap arithmetic; the saving is memory. Each cached token stores only the KV heads: 4 × 128 numbers per layer for Qwen2.5-7B against 8 × 128 for Mistral-7B, times 2 for keys and values, times 2 B each, times the 28 and 32 layers — 57,344 B against 131,072 B per token in bf16. Chapter 6 turns this into the full roster table.

One layer's attention, in five steps; the pinned code does the lookup in five moves, and the cache write sits in the middle:

  1. Project. The scaled hidden vector goes through three matrices — q, k, v. Qwen2.5-7B's q and k projections output 3,584 and 512 numbers respectively: 28 heads × 128 wide, 4 heads × 128 wide.
  2. Position. Queries and keys rotate by their position (chapter 3's RoPE); values stay put.
  3. Cache. The new keys and values append to this layer's running KV tensor — the write you pay for on every step that generates a token: past_key_values.update(key_states, value_states, self.layer_idx).
  4. Score and blend. Each query dot-products against the cached keys, the mask (the window of 1.4) removes forbidden positions, the scores squeeze to a mix, and the weighted values add up.
  5. Project out. The blended heads concatenate and pass through the output matrix, back to 3,584 numbers, ready for the feed-forward.

The call to the attention function takes the appended keys and values and returns the blend ; the output projection closes the step . Every layer of the 28 and 32 runs the same five moves on its own weights.

Where the cache lives

The KV tensors live on the same GPU as the weights, one keys and one values tensor per layer, [batch, heads, so-far tokens, head_dim], appended in place every step . The append is a concatenation . Engines re-lay this out across memory pages — the sibling courses' subject; the course's memory budgets in chapter 20 read this shape directly.

Easy to get wrong

Fewer KV heads do not mean fewer query heads or a smaller model. The queries stay at full count and full width; only what gets cached shrinks. A 7x repeat factor reads oddly until you see it this way: 28 queries, 4 memories.

1.4The window that isn't

Mistral-7B's other efficiency idea is a sliding window of 4,096 : each token attends to the last 4,096 positions, so a 32,768-token context never pays full quadratic attention. In Transformers the window is a mask choice, one branch next to the causal default:

Qwen2.5-7B sets its window to 131,072 and then switches the mechanism off with use_sliding_window: false . Its 131,072-token context runs full attention. Mixtral-8x7B goes further and sets the window to null . Three settings of the same key, three attention bills: capped, full, and absent. Chapter 7 follows the window through gpt-oss-120B's 128-token extreme.

1.8Check yourself

Qwen2.5-7B runs a forward pass over a 10-token sequence. What does the last layer produce for the server to pick token 11 from?

  1. The text of the most likely word
  2. The id of the most likely next token
  3. 152,064 logits, one per vocabulary entry, which the server turns into a choice
  4. A probability for each of the 10 input tokens
The untied LM head scores every entry of the 152,064-word vocabulary. Picking one, by argmax or sampling, is the server's job — which is why the sampler lives in the engine, not the model.

Qwen2.5-7B has 28 query heads and 4 KV heads. What does repeat_kv do before attention?

  1. Averages the 28 queries down to 4
  2. Repeats each KV head 7 times so 28 queries each have keys and values
  3. Projects the 4 KV heads up to 28 with a learned matrix
  4. Nothing: 4 KV heads serve 28 queries directly
28 / 4 = 7. The repeat is a view-level copy, not a learned projection, which is why the saving is memory (what gets cached) rather than arithmetic.

Mistral-7B reads a 10,000-token prompt. Which tokens can position 9,999 attend to?

  1. Roughly the last 4,096: positions 6,004–9,999
  2. All 10,000 positions
  3. Only position 9,998
  4. The first 4,096: positions 0–4,095
The sliding window is 4,096 back from the current position. Qwen2.5-7B would attend to all 10,000; its window mechanism is off.

Mixtral-8x7B routes one token with top-2 of 8 experts. About how many feed-forward weights does that token touch per layer?

  1. One expert: about 176M
  2. All eight: about 1.4B
  3. None: the router replaces the feed-forward
  4. Two experts: about 352M, plus 42M of attention
Each expert holds 3 × 4,096 × 14,336 ≈ 176M weights and the token visits two. The other six stay resident but untouched — the active-vs-resident gap Part III is about.
Takeaways
  • One decoder block — RMSNorm, grouped-query attention, RMSNorm, SwiGLU, two residuals — underlies every roster model.
  • KV heads are shared and repeated (×7 in Qwen2.5-7B, ×4 in Mistral-7B). Only the KV heads get cached: 57,344 B vs 131,072 B per token in bf16.
  • The window is a mask choice: 4,096 on, 131,072 off, null in Mixtral. Same key, three attention bills.
  • The MLP dominates the block, so experts, sparsity and narrow formats attack it first. Mixtral previews the pattern: 2 of 8 experts awake.
  • Neither model ties embeddings, so the vocabulary is paid twice. Vocabularies are chapter 2.
