One forward pass can commit to more than one token two ways: train extra heads to predict ahead, or draft cheaply and verify once. DeepSeek-V3 trains one prediction layer; GLM-5.3 trains one; V4.1-Flash trains three and ships a 5-token speculative block called DSpark. Kimi-K2 trains zero. This chapter generates three tokens twice: three sequential target passes on channel A, draft-and-verify on channel B.

The 2-minute version

MTP trains extra futures (1–3 layers); drafting spends them at serve time by verifying cheap proposals with one target pass. Yield is a formula in acceptance rate — measured per workload, never assumed.

After this chapter you can: read prediction depths from a config · trace DSpark's block machine · compute expected yield for any acceptance rate.

21.1Draft three, verify once

The figure sets acceptance as a parameter, not a claim: suppose 2 of 3 drafts verify. Then one target pass yields 2 tokens plus a correction, against 3 passes for 3 tokens sequential. Change the supposition and the arithmetic follows — the mechanism is exact, the rate is yours. No acceptance numbers in this course come from a measurement; the course has no GPU.

21.2Prediction layers in the config

Multi-token prediction trains the model to predict several futures at once, which enriches the shared representations and leaves draft heads behind for serving. The depth is one config key. V3 and V3.2-Exp train a single layer ; GLM-5.3 trains one beside its DSA stack ; Kimi-K2 trains none :

Transformers v5.9.0 carries the depth as config but implements no next-token-prediction heads for these families — the prediction heads live in vendor modeling, like Kimi-K3's auto-mapped files. The course cites the depth from the config and the mechanism from papers, and keeps the two attributions separate. Zero is also a reading: Kimi-K2's 0 means its speed comes from the KDA hybrid and MXFP4, not from drafts.

21.3A five-token speculative block

V4.1-Flash goes furthest: 3 prediction layers and a DSpark block of 5 — a small Markov drafter (rank 256 ) proposing 5-token blocks with a dedicated noise token , verified against target layers 37–39 :

The draft side is its own tiny MoE — 128 experts with 3 active — so drafting costs a fraction of a target pass while speaking the same expert language. The last three main layers do the verifying, which is why the block targets exactly those depths. Draft quality decides everything downstream, and draft quality is a measured rate the course does not have — hence parameters, not promises, in the figure above.

21.4The acceptance arithmetic

With acceptance probability α per draft token and a block of k drafts, one target pass yields (1 − αk+1) / (1 − α) tokens on average — the standard speculative-decoding expectation, stated here as a formula with α yours to set. At α = 0.8 and k = 3 that is about 2.95 tokens per pass against 1 sequential: the draft cost must stay well under two target passes to win, which is what the 128-expert tiny MoE is for. At α = 0.3 the same block yields about 1.4 tokens and likely loses. The config tells you the block exists and its size; only a measurement on your traffic tells you α. Chapter 29 serves the drafts; the sibling Two Engines course times the target.

Easy to get wrong

MTP training heads and speculative serving are related, not identical. Training heads enrich representations whether or not anyone drafts; drafting needs a verifier and an acceptance rate. A model with prediction layers can serve without drafting, and a model without them (Kimi-K2) can still draft with an external drafter.

21.6Check yourself

What does num_nextn_predict_layers = 3 mean in V4.1-Flash?

  1. The model generates 3 tokens per layer
  2. Three extra heads train to predict further futures, enriching representations and leaving draft heads
  3. Decoding runs 3 times faster, guaranteed
  4. The context window triples
Depth of prediction, not speed directly. Speed needs drafting plus a good acceptance rate; the heads only make drafting possible and training richer.

DSpark drafts 5-token blocks with 128 experts top-3. Why a tiny MoE for drafting?

  1. MoE drafters always accept
  2. The target requires MoE-shaped drafts
  3. Drafting must cost a fraction of a target pass, or verification can't win
  4. 128 experts match the 128-token window
Speculation wins only if drafts are cheap. A 128-expert top-3 drafter speaks the same expert language at a fraction of the 384-expert target's cost.

At acceptance 0.3 per token with a 3-draft block, roughly how many tokens does one target pass yield?

  1. About 1.4 — likely a loss after draft cost
  2. About 3 — the block always fills
  3. About 0.3 — only the correction survives
  4. About 5 — the DSpark block size
(1 − 0.3⁴)/(1 − 0.3) ≈ 1.42. Low acceptance turns speculation into overhead — which is why α is measured on your traffic, never assumed.

Kimi-K2 sets num_nextn_predict_layers = 0. What follows?

  1. It cannot generate text
  2. It must draft with an external model
  3. Its context is limited to one token
  4. Nothing about speed follows: its efficiency comes from KDA hybrid attention and narrow experts
Zero prediction layers means no trained drafts, not no speed. Architectures have several dials; Kimi-K2 turns the attention and format ones instead.

From chapter 9: indexed top-k reads 2,048 of 8,192 cached tokens. Draft-and-verify reads all 3 drafts in one pass. What do both mechanisms share?

  1. Both delete unselected tokens
  2. Both spend one expensive pass over a cheap shortlist instead of full sequential work
  3. Both require MXFP4 weights
  4. Both renormalize router weights
Shortlist, then verify: DSA shortlists positions for attention, speculation shortlists tokens for the target. The expensive pass runs once either way.
Takeaways
  • MTP trains extra futures (1, 1, 3, 0 layers across V3, GLM-5.3, V4.1-Flash, Kimi-K2); drafting spends them at serve time.
  • DSpark is a full speculative machine in config: 5-token blocks, Markov drafter, verify at layers 37–39.
  • Yield is a formula in acceptance α; α is measured per workload, never assumed.
  • Training heads and serving drafts are related, not identical — either can exist without the other.
