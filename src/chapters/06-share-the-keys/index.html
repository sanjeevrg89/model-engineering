The 2-minute version

KV heads are a memory knob: Qwen3-8B shares 32 queries over 8 heads, gpt-oss-120B shares 64 over 8 narrow heads inside a 128-token window. Fewer, narrower heads plus a short window turn 144 MiB of KV reads into 9 MiB for the same 1,024 cached tokens.

After this chapter you can: compute any model's repeat factor and KV bytes from its config · explain why V4.1-Flash's single KV head works · price a full context in GiB.

6.1One knob, three settings

Multi-head attention gives every query head its own KV heads. Multi-query attention gives the whole layer one. Grouped-query attention lands between: 8 groups in Qwen3-8B and in gpt-oss-120B , 4 in Qwen2.5-7B, 1 in V4.1-Flash's text stack . The query count never moves with the knob: 32, 64 and 64 queries respectively. Only what gets cached shrinks — and gpt-oss halves head dim to 64 for a second halving on top.

The extremes

LLaDA-8B keeps full multi-head attention (32 queries, 32 KV heads) because bidirectional denoising never reuses a cache. DeepSeek-V2-Lite keeps 16 and 16 and compresses instead — chapter 8.

6.2The repeat on the hot path

Transformers sizes the projections by the KV count and repeats on the way into attention. The class holds the group count; the eager path calls the repeat every forward pass:

The repeat is a view-level copy before the matmul, so it costs arithmetic proportional to what attention would have read anyway. The saving is everything around it: smaller K/V projections, smaller optimizer states in training, and above all a smaller cache. Qwen3-8B repeats ×4, gpt-oss-120B ×8, V4.1-Flash ×64. The ×64 looks extreme until the next section's table shows what it buys at 1M context — and gpt-oss pairs its ×8 with a 128-token window, so the saving compounds.

Who holds that cache: the model's DynamicCache, updated in place at line 270 of LLaMA's attention forward by concatenating the new keys and values onto per-layer tensors — one CacheLayer per model layer , resident beside the weights on the accelerator. Chapter 1's five-step walk places the write between positioning and scoring.

Easy to get wrong

Head dim is not always hidden divided by heads. MLA models route through latent ranks (512) and split heads (128+64); V4.1-Flash sets head_dim 512 outright with 64 queries over 1 KV head. Read the rank keys, don't divide.

6.6Check yourself

gpt-oss-120B has 64 query heads and 8 KV heads of width 64. What is its repeat factor, and what does it multiply?

  1. ×8: each query head is used 8 times
  2. ×8: each KV head is repeated 8 times to serve 64 queries
  3. ×64: the KV cache is 64 times smaller than MHA
  4. ×36: layers times KV heads
64 / 8 = 8, applied to keys and values before the matmul. Narrow heads (64, not 128) halve the bytes a second time — two halvings stacked.

How many KV bytes does one gpt-oss-120B token occupy in bf16, and how far do they multiply?

  1. 57,344 B across the full context
  2. 131,072 B across the full context
  3. 73,728 B, never past 128 positions
  4. 376,832 B across the full context
2 × 36 layers × 8 heads × 64 × 2 B = 73,728 B, and the 128-token window caps the multiplication. Small heads times a short window.

DeepSeek-V4.1-Flash runs 64 query heads over 1 KV head. What does that imply?

  1. A ×64 repeat with the smallest per-layer KV read on the roster, paired with compression
  2. 64 times more KV cache than Mistral-7B
  3. No attention at all in the text stack
  4. The same cache as 64-head MHA
One 512-wide KV head per layer is the MQA extreme; the model pairs it with 4 full-context source layers and a 128-token window rather than caching everything.

Why can't you compute MLA models' cache with 2 × layers × KV heads × head_dim?

  1. They have no attention layers
  2. Their head_dim is always 512
  3. They share one KV head across all layers
  4. They cache a low-rank latent, not per-head keys and values
DeepSeek-V2-Lite's 16 KV heads never materialize as a cache; the 512-number latent does. Chapter 8 weighs it: 31,104 B per token across 27 layers.

From chapter 1: one Qwen2.5-7B block holds about 233.0M weights. How much of that is attention?

  1. 203.7M — the MLP is the minority
  2. 29.4M — the MLP dominates at 203.7M
  3. 116.5M — attention and MLP split evenly
  4. 57,344 — the KV bytes, not weights
29.4M attention against 203.7M feed-forward — which is why later chapters put experts, sparsity and narrow formats in the MLP first. Option d confuses bytes with weights.
Takeaways
  • KV heads are a memory knob from 1 to 128; queries stay at full count and the repeat is cheap.
  • One formula prices standard attention; windows cap the multiplication and latents replace the cache.
  • Head dim is a config value, not hidden divided by heads — read the rank keys.
  • MLA compresses what GQA shares; that is chapter 8.
