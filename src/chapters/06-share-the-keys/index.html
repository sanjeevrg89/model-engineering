Chapter 5 counted weights. This chapter counts the other bill: the keys and values every past token leaves behind. Mistral-7B stores 8 heads per layer, Qwen2.5-7B stores 4, DeepSeek-V4.1-Flash stores 1. Same queries, same model quality discipline, three memory bills — and the roster stretches from 1 to 128 KV heads.

The figure reads one decode step's KV memory for 1,024 cached tokens, layer by layer: Mistral-7B on channel A, Qwen2.5-7B on channel B. Watch the per-layer width first, then the totals, then the moment B runs out of layers and A keeps reading.

6.1One knob, three settings

Multi-head attention gives every query head its own KV heads. Multi-query attention gives the whole layer one. Grouped-query attention lands between: 8 groups in Mistral-7B , 4 in Qwen2.5-7B , 1 in V4.1-Flash's text stack . The query count never moves with the knob: 32, 28 and 64 queries respectively. Only what gets cached shrinks.

The extremes

LLaDA-8B keeps full multi-head attention (32 queries, 32 KV heads) because bidirectional denoising never reuses a cache. DeepSeek-V2-Lite keeps 16 and 16 and compresses instead — chapter 8.

6.2The repeat on the hot path

Transformers sizes the projections by the KV count and repeats on the way into attention. The class holds the group count; the eager path calls the repeat every forward pass:

The repeat is a view-level copy before the matmul, so it costs arithmetic proportional to what attention would have read anyway. The saving is everything around it: smaller K/V projections, smaller optimizer states in training, and above all a smaller cache. Qwen2.5-7B repeats ×7, Mistral-7B ×4, V4.1-Flash ×64. The ×64 looks extreme until the next section's table shows what it buys at 1M context.

Easy to get wrong

Head dim is not always hidden divided by heads. MLA models route through latent ranks (512) and split heads (128+64); V4.1-Flash sets head_dim 512 outright with 64 queries over 1 KV head. Read the rank keys, don't divide.

Write three functions over the pinned fixture configs: the repeat factor, KV bytes per token, and cache bytes for a full context. The tests check Qwen2.5-7B, Mistral-7B, gpt-oss-120B and V4.1-Flash, including the ×64 repeat and the 7.0 GiB Qwen context. Dividing hidden by heads instead of reading the rank is the classic mistake, and the MLA test catches it.

6.6Check yourself

Qwen2.5-7B has 28 query heads and 4 KV heads. What is its repeat factor, and what does it multiply?

  1. ×4: each query head is used 4 times
  2. ×7: each KV head is repeated 7 times to serve 28 queries
  3. ×28: the KV cache is 28 times smaller than MHA
  4. ×32: layers times KV heads
28 / 4 = 7, applied to keys and values before the matmul. The cache saving versus 28 KV heads is 7x; the repeat itself is nearly free arithmetic.

How many KV bytes does one Mistral-7B token occupy in bf16?

  1. 57,344 B
  2. 73,728 B
  3. 131,072 B
  4. 376,832 B
2 × 32 layers × 8 heads × 128 × 2 B = 131,072 B. The 57,344 B answer is Qwen2.5-7B; 376,832 B is 92-layer GLM-4.5.

DeepSeek-V4.1-Flash runs 64 query heads over 1 KV head. What does that imply?

  1. A ×64 repeat with the smallest per-layer KV read on the roster, paired with compression
  2. 64 times more KV cache than Mistral-7B
  3. No attention at all in the text stack
  4. The same cache as 64-head MHA
One 512-wide KV head per layer is the MQA extreme; the model pairs it with 4 full-context source layers and a 128-token window rather than caching everything.

Why can't you compute MLA models' cache with 2 × layers × KV heads × head_dim?

  1. They have no attention layers
  2. Their head_dim is always 512
  3. They share one KV head across all layers
  4. They cache a low-rank latent, not per-head keys and values
DeepSeek-V2-Lite's 16 KV heads never materialize as a cache; the 512-number latent does. Chapter 8 weighs it: 31,104 B per token across 27 layers.
Takeaways
  • KV heads are a memory knob from 1 to 128; queries stay at full count and the repeat is cheap.
  • One formula prices standard attention; windows cap the multiplication and latents replace the cache.
  • Head dim is a config value, not hidden divided by heads — read the rank keys.
  • MLA compresses what GQA shares; that is chapter 8.
