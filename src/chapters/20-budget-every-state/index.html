Every architecture leaves a per-token receipt, and no two receipts look alike. Qwen2.5-7B leaves 57,344 bytes of KV. DeepSeek-V3.2-Exp leaves a 70,272-byte latent plus indexer keys. Kimi-K3 leaves 27,648 bytes of latent on 24 layers and fixed recurrent state on 69. LLaDA leaves nothing reusable at all. This chapter totals one token's leftovers twice: Qwen2.5-7B's pure KV on channel A, V3.2-Exp's latent-plus-index on channel B — then tables all fifteen.

The 2-minute version

Four state kinds: standard KV, MLA latent, fixed recurrent state, indexer keys. Receipts run from 0 B (diffusion) to 376,832 B (92-layer GQA) per token — price one row's kinds, never the columns' sum.

20.1Two receipts for one token

Four kinds of state exist on the roster. Standard KV grows with heads, layers and width. MLA latents grow with rank and layers. Recurrent states (Mamba-2, Gated DeltaNet, KDA, Lightning) are fixed per layer no matter the context. Indexer keys grow with index heads and width, and diffusion keeps no cache because bidirectional attention never reuses one. The figure stacks A's single kind against B's two; the table prices all four.

20.2Four kinds of leftovers

Standard KV is 2 × layers × KV heads × head_dim × bytes. Seven roster models pay it, from 57,344 B (Qwen2.5-7B) to 376,832 B (GLM-4.5), with gpt-oss-120B's narrow heads at 73,728 B — chapter 6's table, unchanged.

MLA latents are layers × (rank + rotary) × bytes: 31,104 B for V2-Lite, 70,272 B for V3, Kimi-K2 and V3.2-Exp, 89,856 B for GLM-5.3 over 78 layers, 27,648 B for Kimi-K3 over its 24 full layers. V4.1-Flash compresses further: 4 source layers hold full context and the rest read those :

Recurrent state is constant per layer: Kimi-K3's 69 KDA layers carry it beside 24 MLA layers , and MiniMax-M2.5's config carries a 62-entry per-layer type list whose kinds the vendor modeling assigns — all entries read code 1 at this revision, so the course does not infer splits from the config; chapter 19 takes the hybrid story from release notes.

Indexer keys are tokens × index heads × index width × bytes: GLM-5.3's 32 × 128 keys cost 1 GiB at 131,072 tokens in bf16 — the price of knowing what to read, from chapter 9's lab.

Easy to get wrong

Adding the columns is the mistake this chapter exists to prevent. A token's receipt is one row's kinds, not every column: KV or latent or fixed state, plus an indexer's keys where one exists. Summing KV and latent double-counts designs that keep only one.

20.5Check yourself

A Qwen2.5-7B token and a V3.2-Exp token each leave state behind. What are the two receipts?

  1. 57,344 B of latent vs 70,272 B of KV
  2. 57,344 B of KV vs 70,272 B of latent plus indexer keys
  3. Both leave 70,272 B of latent
  4. Neither leaves state: both use sliding windows
Standard KV on A, compressed latent plus a scorer's keys on B. Different kinds, different formulas — never add the columns.

Kimi-K3's 27,648 latent bytes cover 24 layers. What holds the other 69?

  1. Full KV caches at 69 × 576 numbers
  2. Nothing — those layers are stateless
  3. Fixed-size KDA recurrent state, constant in context length
  4. A second MLA latent of rank 256
69 KDA layers carry fixed state; only the 24 full-attention layers grow a cache. That split is the hybrid's memory story.

V4.1-Flash names 4 kv_source layers out of 40. What does that imply?

  1. 4 layers store full context; the other 36 read those stores instead of keeping their own
  2. Only 4 layers run attention
  3. The model has 4 layers total
  4. KV heads are shared across 4 layers
Store where it pays, read everywhere. Compression moves the cache off most layers without removing their access — chapter 21 opens the ratios.

Why is LLaDA-8B's receipt zero?

  1. It has no attention layers
  2. Its context is length zero
  3. Its weights are quantized to zero bits
  4. Bidirectional denoising never reuses past computation, so there is no cache to keep
KV caches exist to reuse past positions in left-to-right decoding. Diffusion refines the whole sequence every step — nothing is reusable, nothing is stored. Chapter 25.

From chapter 6: Qwen2.5-7B's 57,344 B receipt comes from which multiplication?

  1. 2 × 28 layers × 4 KV heads × 128 × 2 B
  2. 28 layers × 512 latent × 2 B
  3. 2,048 winners × 28 layers
  4. 152,064 vocab × 3,584 width
Keys and values, layers, heads, width, bytes. The formula prices standard attention only — latents and fixed states need their own.
Takeaways
  • Four state kinds: standard KV, MLA latent, fixed recurrent state, indexer keys. Price the row's kinds, never the columns' sum.
  • Receipts run from 0 B (diffusion) to 376,832 B (92-layer GQA) per token in bf16.
  • Compression moves storage off layers; selection moves reads off tokens; neither deletes.
  • Full context multiplies the receipt — chapter 23 does the multiplication.
