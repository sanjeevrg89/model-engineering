Beyond the chapters

From reader to contributor

New architectures arrive monthly. This page is how a reader turns the next release into a course update: the ten-minute read, the delta paragraph, and the path to a first pull request.

Every chapter ends with a reading list into the real configs and code. This page is for the step after reading: a new model drops, and you want the course to cover it.

1The ten-minute read

  1. Open the release's config.json on the Hub. Read heads, KV heads, layers, experts, ranks, windows, theta — the same keys every roster table uses.
  2. Find its modeling file in Transformers. Diff the attention and MoE blocks against the closest roster model.
  3. Read the paper or release note once, for what the authors claim changed and why.

Chapter 30 walks this end to end. If the config is gated behind login, stop: the course only pins publicly fetchable revisions.

2Write the delta first

A new architecture joins the course as a cited delta: one paragraph in the relevant chapter, a paper or release-note link, and what changed relative to the roster. No config values from memory, no parameter counts from press coverage. It graduates to the pinned roster when its config is fetchable and two chapters cite it.

3Open the pull request

One delta per pull request, with the fetch command, the strict build output and the recomputed rows of research/models.json. The checklist in AUTHORING.md is the review: pins, refs, figures, lab, quiz, voice.
